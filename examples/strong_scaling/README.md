# LAMMPS Strong Scaling Analysis for ParslBox

This directory contains scripts for orchestrating and analyzing LAMMPS strong scaling tests using ParslBox.

## Files

- `lammps_strong_scale_orchestrator.py` - Main orchestrator script that creates jobs
- `plot_strong-scale-results.py` - Analysis script that processes results and creates plots
- `python_env-setup.sh` - Environment setup script for the analysis
- `README.md` - This documentation file

## Quick Start

1. **Prepare your input files** in a working directory:
   - LAMMPS input file (e.g., `in.lammps`)
   - Structure/data file (e.g., `data.lmp`, `model.lmp`)
   - Force field file (e.g., `pair_coeff.dat`, `forcefield.dat`)

2. **Copy the scripts** to your working directory:
   ```bash
   cp /path/to/parslbox/examples/strong_scaling/*.py .
   cp /path/to/parslbox/examples/strong_scaling/*.sh .
   ```

3. **Run the orchestrator** to create jobs:
   ```bash
   python lammps_strong_scale_orchestrator.py polaris --gpus 1 2 4 --fstruct data.lmp --ff pair_coeff.dat
   ```

4. **Submit and monitor jobs**:
   ```bash
   pbx qsub          # Submit all jobs
   pbx ls            # Monitor job status
   ```

5. **Results will be generated automatically** when all jobs complete, or run analysis manually:
   ```bash
   python plot_strong-scale-results.py
   ```

## Detailed Usage

### Orchestrator Script

```bash
python lammps_strong_scale_orchestrator.py <config_name> --gpus <gpu_counts> --fstruct <structure_file> --ff <forcefield_file> [options]
```

**Required Arguments:**
- `config_name` - System configuration (e.g., `polaris`, `crux`, `sophia`)
- `--gpus` - Space-separated list of GPU counts (e.g., `--gpus 1 2 4 8`)
- `--fstruct` - Structure/data file name
- `--ff` - Force field file name

**Optional Arguments:**
- `--in` - LAMMPS input file name (default: `in.lammps`)
- `--tag` - Job tag for organization (default: `strong_scale`)

**Examples:**
```bash
# Basic strong scaling test
python lammps_strong_scale_orchestrator.py polaris --gpus 1 2 4 --fstruct data.lmp --ff pair_coeff.dat

# Custom input file and more GPU counts
python lammps_strong_scale_orchestrator.py polaris --gpus 1 2 4 8 --fstruct model.lmp --ff forcefield.dat --in in.friction

# Different system with custom tag
python lammps_strong_scale_orchestrator.py crux --gpus 1 2 --fstruct data.lmp --ff pair_coeff.dat --tag my_scaling_test
```

### What the Orchestrator Does

1. **Creates directories**: `1gpu/`, `2gpu/`, `4gpu/`, etc.
2. **Copies files**: Input files are copied to each GPU directory
3. **Creates jobs**: LAMMPS jobs are added to pbx with proper GPU allocation
4. **Sets dependencies**: Jobs run in sequence (1gpu → 2gpu → 4gpu → analysis)
5. **Adds analysis job**: Python analysis runs after all LAMMPS jobs complete

### Analysis Script

The analysis script runs automatically as the final job, but can also be run manually:

```bash
python plot_strong-scale-results.py [--base-dir DIR] [--output-prefix PREFIX]
```

**Options:**
- `--base-dir` - Directory containing GPU subdirectories (default: current directory)
- `--output-prefix` - Prefix for output files (default: `strong_scaling`)

### Generated Output Files

The analysis script generates several files:

1. **`strong_scaling_performance.png`** - Performance vs GPU count plots
2. **`strong_scaling_efficiency.png`** - Scaling efficiency and speedup plots
3. **`strong_scaling_data.csv`** - Raw performance and efficiency data
4. **`strong_scaling_summary.txt`** - Summary report with key metrics

All plots are publication-ready with 300 DPI resolution.

## Performance Data Extraction

The analysis script looks for this specific line format in `log.lammps` files:

```
Performance: 2.215 ns/day, 10.834 hours/ns, 25.639 timesteps/s, 63.483 katom-step/s
```

It extracts the performance data from the **bottom** of the log file (most recent data) and uses:
- `timesteps/s` for primary scaling analysis
- `katom-step/s` for secondary analysis
- Other metrics are recorded but not used in scaling calculations

## Scaling Metrics

The analysis calculates:

- **Speedup**: Performance_N / Performance_1
- **Efficiency**: (Speedup / GPU_ratio) × 100%
- **Ideal scaling**: Linear relationship for comparison

Modify this script based on your system's module environment.

## Troubleshooting

**Common Issues:**

1. **No performance data found**: Check that LAMMPS jobs completed successfully and `log.lammps` files contain the performance line.

2. **Module not found errors**: Ensure the environment setup script is properly configured for your system.

3. **Job dependency issues**: Check job IDs and dependencies with `pbx ls`.

4. **Permission errors**: Ensure scripts are executable: `chmod +x *.py *.sh`

**Debugging:**

- Check individual log files in GPU directories
- Verify job status with `pbx ls --status Failed`
- Run analysis script manually to see detailed error messages
