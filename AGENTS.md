# AGENTS.md

ParslBox (`pbx`) orchestrates HPC jobs: register job directories in a local
SQLite database, then submit them to PBS or SLURM, where a Parsl-based engine
packs them onto the allocation's nodes.

The detailed instructions live in three skills under `skills/`. Each is
self-contained — read them straight from this clone; they do not need to be
installed first.

## Setting parslbox up

Follow [`skills/pbx-setup/SKILL.md`](skills/pbx-setup/SKILL.md). It is a
playbook covering the whole job: working out which machine will run the jobs,
installing parslbox into a Python environment, choosing systems and apps,
writing `config.yaml`, and filling in the values it leaves blank.

Two things that catch people out, both handled by the playbook:

- **A generated config is a scaffold, not a working setup.** `pbx_python_env_setup`
  for each system and `executable_path` for each compiled app start as
  placeholders. Jobs fail later if they are left that way, so do not stop at
  "config written".
- **The `/pbx-setup` slash command does not exist until the skills are
  installed and the harness restarted.** That is no obstacle — follow the file.

## Working on this repo

```bash
python -m pytest tests/ --tb=short     # full suite; run after any change
scripts/sync-skill-docs.sh             # after editing docs/
scripts/sync-skill-docs.sh --check     # fails if a bundled copy is stale
```

- **The CLI, the Python API and the MCP server are three faces of the same
  behaviour and must stay aligned.** A behaviour change belongs in the shared
  helper they all call, not in one layer.
  - CLI (`parslbox/commands/`) — Rich tables and panels
  - API (`parslbox/api.py`) — returns dicts, raises typed exceptions
  - MCP (`parslbox/mcp/`) — short strings; schemas in `parslbox/mcp/schemas.py`,
    which is all an LLM caller sees, so new syntax must be described there
- Tests: CLI → `tests/test_<command>_command.py`, API → `tests/api_tests/`,
  MCP → `tests/test_mcp_server.py`.
- `docs/` is canonical. `skills/*/docs/` are generated byte copies — edit the
  former and run the sync script, never the copies.
